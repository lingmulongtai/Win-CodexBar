# Win-CodexBar + Mobile Connect v0.70.6

Fix Gemini Apps connections that worked immediately after import and then lost access. Previous versions replayed the original cookies and discarded Google session updates. This release carries renewed cookies from bootstrap to quota requests and later refreshes, and attempts periodic renewal through the fixed Google Accounts endpoint.

- Keep renewed sessions in a separate Windows-user DPAPI file bound to the selected login. Background renewal preserves Android's credential-selection stamp, so a successful refresh stays available to paired phones/tablets.
- Reject late renewal writes after disconnect, credential revocation or reconnect, including a reconnect with identical original cookie bytes. Renewed credentials never enter usage exports or frontend DTOs.
- Save the session verified during initial connection, rather than the original pre-verification snapshot. Keep the previous connection when verification fails.
- Parse the bootstrap CSRF property even when its name appears earlier in a list. Distinguish an explicitly signed-out page from a changed response schema.
- Preserve HTTP/1.1, TLS verification, fixed Google origins, redirect rejection and cookie scope/deletion checks. No dependencies were added.

If your existing connection already expired, update the Windows EXE and connect Gemini Apps once more. Android v0.9.8 remains compatible; this fix does not require a new APK.

[Gemini Apps setup and limitations](../gemini-apps.md) · [Phone/tablet and Tailscale setup](../android-sharing.md)

The direct EXE requires Windows 10/11 x64 and WebView2 Runtime. It is unsigned. Verify `SHA256SUMS` and `build-provenance.json`, quit the resident app, replace the EXE and relaunch.
