# Win-CodexBar + Mobile Connect v0.70.3

Vivaldi now appears as a separate browser choice in **Settings → provider → Browser Cookies** when its standard Windows profiles are present. The same catalog also enables Vivaldi in existing Chromium browser-storage discovery.

- Detects `%LOCALAPPDATA%\Vivaldi\User Data`, including `Default` and additional `Profile N` profiles; stable import ID: `vivaldi`.
- Uses the existing Chromium DPAPI/AES-GCM cookie reader and selected-browser import route. Importing from Vivaldi does not fall back to a different browser.
- Adds Vivaldi to browser-import guidance in every supported locale.
- Covers browser catalog identity, absent/installed profile detection, profile ordering, cookie/key file locations, and browser-specific App-Bound Encryption errors with regression tests.

App-Bound (`v20`) cookies remain unsupported; the app explains the limitation and keeps the existing manual Cookie-header fallback. Custom standalone profile locations are not automatically discovered. Sign in to the service in Vivaldi before importing. Existing Windows/Android pairing and saved settings are retained; Android v0.9.7 works with this release.

The direct Windows EXE remains unsigned and requires Windows 10/11 x64 plus WebView2 Runtime. Verify `SHA256SUMS` and `build-provenance.json`, exit the running app, replace the EXE and relaunch.
